# Documentation and graphic design rationale

This is an independent documentation design adapted from published principles, not a Toss or KRDS certification, affiliation, or complete implementation of either component library.

## Source guidance

- [Toss Design System colors](https://tossmini-docs.toss.im/tds-react-native/foundation/colors/): shared named neutrals and a restrained primary accent.
- [Toss accessibility: reading order](https://toss.tech/article/voiceover_usability): organize meaningful information in a usable sequence.
- [KRDS typography](https://www.krds.go.kr/html/site/style/style_03.html): clear heading/body hierarchy and legible text.
- [KRDS layout](https://www.krds.go.kr/html/site/style/style_05.html): consistent alignment, margins and spacing.

## Applied rules

The README leads with purpose and enabled work, then offers implementation evidence and reproduction steps. Detailed material is linked instead of squeezed into a dense hero image. Normal paragraphs remain text so they can be selected, translated, resized and read by assistive technology.

Original SVG diagrams use white backgrounds, dark neutral labels, a consistent blue accent, generous padding and a single left-to-right flow. Each diagram has an accessible title/description and a textual equivalent in the surrounding document. State and result claims are written as words; color is never the only carrier of meaning. No logo or certification mark is copied.

The palette is #191f28 for headings, #4e5968 for body text, #1b64da for accent and #f2f4f6 for secondary surfaces. These are visual choices for this documentation. GitHub controls Markdown typography, so the documents do not claim control over GitHub's CSS or conformance of its entire interface. Scientific graphs include axes, units, legends and the source of their data.
